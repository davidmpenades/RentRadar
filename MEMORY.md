## Riesgos conocidos (detalle en la skill indicada)
- Backend (Nominatim, 403/401 con sesión, locks de pip, caché por proceso): ver skill django-drf. Frontend: jsdom no calcula layout (overflow y responsive, en navegador real); los mocks de fetch respetan AbortSignal y ordenan sus claves de más a menos específica. → testing
- Las afirmaciones de un agente se comprueban contra el código. Montaje de un fichero individual (./.env.example): un `sed -i` en el host cambia el inode y el contenedor sigue viendo el antiguo; se arregla recreando el contenedor.
- Tests: solo dentro del contenedor (geteuid == 10001) y con el loopback bloqueado por el fixture de red; psycopg resuelve el host en Python, así que una segunda conexión a la BD también queda bloqueada.

## Aprendizajes de este proyecto
- El backend postgis de Django crea la extensión en migrate (prepare_database); la 0001 sirve para BD gestionadas. La semilla de categorías vive en la BD de test: un test con transaction=True la vaciaría (usar serialized_rollback).
- Las herramientas de edición convierten \uXXXX en el carácter literal: los escapes se escriben desde un script con chr(92). Los tests no llevan caracteres invisibles (NBSP, tildes descompuestas, ligaduras) literales; se comprueba por categoría Unicode.
- Pruebas de mecanismo: cada mutación sobre copia del fichero, con sha256 antes y después y restauración, sin plugins de pytest ni ficheros en /tmp; migraciones con `pytest --create-db`; reglas por AST con un módulo temporal bajo backend/apps borrado en el mismo comando. Si una mutación sobrevive, se explica o se añade el test que falta.
- Tests de servicios: se parchean los nombres donde se usan (`apps.<app>.services`), las funciones privadas son keyword-only y un `select_for_update` se verifica por el orden del SQL con `CaptureQueriesContext` (la red bloqueada impide una segunda conexión).
- maplibre-gl 6: sin export por defecto; el worker con `?worker&url` y setWorkerUrl; las opciones de la fuente pisan al TileJSON (la atribución se sustituye en el estilo descargado); imágenes con `?no-inline` para cerrar img-src a 'self'. Ruff aplica 88 columnas también a los comentarios; para ver ficheros nuevos en `git diff`, `git add -N`.
- DRF: la clase que un setting nombra no puede vivir en un módulo que importe rest_framework.views (import circular, lo vigila test_api_import.py). Con DEBUG el SQL registrado lleva ubicación y hash: los tests de logs usan la configuración real (INFO). drf-spectacular publica como obligatorio todo campo read_only: en un serializer que solo documenta, los opcionales no llevan read_only.
- React copia el valor de un campo controlado al atributo value del DOM, también en type="password": las contraseñas van en campos no controlados. La forma abreviada del proxy de Vite (`"/api": url`) activa changeOrigin: true; hay que usar un objeto con changeOrigin: false.
- tsc rechaza ficheros que solo difieren en mayúsculas (TS1149) y vitest no lo detecta. Una sesión de Claude Code en segundo plano exige worktree (el bind mount de Docker no vería los cambios): abrir siempre la sesión principal en primer plano desde la raíz del repo. Los implementers sí pueden ir en segundo plano desde ella, sobre el mismo checkout, si esta no edita ficheros mientras trabajan.
- Entorno (MCP de Chrome): al cerrar Claude Code pueden quedar procesos de Chrome del MCP o un «claude daemon run --origin transient» (comprobar con pgrep). El MCP no escribe fuera de su raíz. Con emulate, pasar de no móvil a móvil recarga la página. El cliente reintenta una vez ante csrf_failed, así que el aviso de salida se provoca cortando la red. En el portátil la métrica de fotogramas está saturada.
